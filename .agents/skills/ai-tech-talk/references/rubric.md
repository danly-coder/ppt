# Acceptance rubric (0–2 per item)

1. Audience: opening uses a concrete case, minimal jargon, non-engineers can explain the goal.
2. Narrative: slides answer a coherent sequence of why/how questions rather than listing definitions.
3. Sources: claim → primary link; comparisons are fair and version-aware.
4. Core diagrams: Agent Loop, Harness control plane, State vs Memory; all editable.
5. Accuracy: no fabricated benchmarks, RSI discussion marked exploratory.
6. Notes: every slide has a presenter explanation plus transition.
7. Discussion: >=3 nontrivial questions about design tradeoffs, not quiz questions.
8. Density: one takeaway per slide, readable at 16:9, no paragraphs of 100+ characters in a single box.
9. QA: can rebuild from source, automated checks pass, visual inspection logged.
10. Reuse: new event topic requires configuration/content edits, not rewriting renderer.

Target >= 16/20 for meetup-ready deck; any invented source or unverified current claim is an automatic release blocker.
